# План: XPBD-физика как библиотека и её внедрение в игру (25.10.2026)

**Где мы сейчас.** `:physics` — самостоятельное ядро: не знает о Gdx, `:core` и `:render`,
держит тела в плоских массивах (`BodyState`) и считается по воркерам побитово так же, как в
одном потоке (~4x на 7 воркерах для 100k). В нём есть сон, ближняя широкая фаза и разрушение.
Клиент у него один — стенд `:physics-lab`. Игра (`:core`) живёт на старой физике
(`systems/physics`: `ParticlePhysicsSystem`, `LinkPhysicsSystem`, `CollisionManager`,
`GridManager`, `MovementManager`).

**Цель.** Игра получает физику через узкий API мира, а не через внутренности `BodyState`.
Ядро остаётся библиотекой: его можно гонять без игры (стенд, проверки, сервер), а границу
держит компилятор — зависимость только `:core → :physics`.

## 1. Решения (25.10)

1. **Обратной совместимости нет.** 0.2.4 ещё не выпущена, отчёты `.bug` появились в ней же,
   отчётов игроков пока нет. Новая физика просто заменяет старую: новый номер формата
   сессии и `StateHash.VERSION++`. Ни переключателя, ни второго движка, ни отдельной
   сборки ради старых повторов.
2. **Все массивы держит библиотека:** позиции, скорости, prev, топологию, раскладку (арены,
   блоки, RCM). Сущности игры держат номер тела и смещение клетки в нём и читают
   координаты по прямой ссылке на массив, без копий. `ParticleEntity` теряет x/y/vx/vy;
   все читатели в игре (сенсоры, поедание, рендер, сохранение, выделение мышью)
   переходят на мир физики. Это самая объёмная часть переноса.
3. **Острова террейна — отдельные тела, а не скопление частиц.** Террейн будет переделан:
   остров — неподвижное тело мира физики (`invMass = 0`). Сталкиваются только вершины
   контура, а неподвижные лежат в неподвижной сетке контактов, которая строится один раз.
   Значит остров стоит почти ничего, сколько бы он ни занимал места. Стенки чашки — так же.
   **Субстанции** — свободные частицы мира (частица без связей — свой организм). Пока их
   немного, отдельного решения не нужно; если станет много — замер (п. 8).
4. **Остаётся double.** Замер `SolverBench` на телефоне — справочный (TODO, раздел
   Android): знать цену, но решение уже принято.

## 2. Контракт библиотеки — этап A, внутри `:physics`

Новый фасад `PhysicsWorld` поверх нынешнего `BodyState`: без объектов на ограничение и без
виртуальных вызовов в горячих циклах.

| Вход | Что это |
|---|---|
| `PhysicsWorld(config, workers)` | Материал (`PhysicsConfig.snapshot`) и исполнитель стадий. |
| `addBody(BodyDescriptor): BodyId` | Полная запечённая раскладка организма: частицы, радиусы, массы, связи, треугольники, кости, мышцы. Порядок — RCM из редактора (`editor/baking/RCMSort.kt`). |
| `addStatic(Contour): BodyId` | Остров террейна или стенка: контур вершин с радиусами, `invMass = 0`. |
| `addFree(x, y, r, mass): ParticleId` | Субстанция. |
| `activate(BodyId, cells)` | Рост: клетки раскладки «рождаются», слоты уже есть, индексы не двигаются (решение 19.10: тело растёт только по запечённому геному). |
| `remove(BodyId)` / `removeFree(ParticleId)` | Смерть организма, исчезновение субстанции; арена — в список свободных, как `Entity.freeRanges`. |
| `setMuscles(BodyId, activations)` | Цели мышц на тик — от нейросети. |
| `applyImpulse` / `setDrag` | Жгутики, реснички, тяга мышью — до шага. |
| `kill(cell)` | Смерть клетки по причине игры (голод, поедание). |
| `step()` | Один тик (`DT`, внутри `SUBSTEPS` подшагов). |

| Выход | Что это |
|---|---|
| `x / y / vx / vy` | Прямые массивы (только чтение по договору) для логики и снимка рендера. |
| `events` | Разрывы, гибель клеток физикой (раздавлена, пробита, давление, долгая инверсия), касания для сенсоров и поедания — буфер на тик в порядке возникновения. |
| `stateHash()` | Часть `journal/StateHash.kt`. |
| `write(out)` / `read(in)` | Полный снимок всего, что влияет на следующие тики. |

Что доделать внутри ядра:
- **Тела в рантайме.** Сейчас `BodySimulation.load` вызывается один раз на набор тел.
  Нужны арены внутри мира: выдача диапазона, блоки решателя по арене, сетка контактов,
  сон, компоненты. Удаление — без пересчёта мира.
- **Рост без смены порядка.** Блоки и план связей строятся по ПОЛНОЙ раскладке арены, а
  нерождённые клетки — это частицы с `invMass = 0` (так уже работают сон и мёртвые
  клетки). Тогда момент рождения клетки не меняет порядок обхода живых, и биты от него
  не зависят.
- **Неподвижные тела.** Контур без внутренних ограничений, только контакты; сразу в
  неподвижную сетку.
- **Полный снимок.** Позиции, скорости, prev, множители контактов (тёплый старт), сон и
  якоря сна, пластика (текущие длины покоя), мёртвые рёбра, пары покоя. Отдельно —
  **состояние широкой фазы** (привязки, следы, список пар): оно влияет на результат
  (ближние пары, поиск пробоя), значит либо пишется в снимок, либо пересобирается в
  известной точке, одинаковой при записи и загрузке. Проверка — побитовое продолжение
  после сохранения посреди прогона.
- **Стенд — первый клиент API.** `DemoSession` переводится на `PhysicsWorld`; все проверки
  (`physicsCheck`, `trapHunt`, `collisionBench`, записи окна, `scaleParityCheck`) обязаны
  остаться побитовыми. API проверяется до того, как его увидит игра.

## 2.1. Устройство этапа A2: тела в рантайме (25.10)

Замер загрузки 100k (прогретый): `buildContacts` 162 мс, `BakedTopology` 96 мс, блоки
решателя 26 мс, план связей 4 мс, остальное ~10 мс. Пересобирать мир на каждое рождение
нельзя — рывок в треть секунды. Поэтому:

1. **Постоянные мира.** Сейчас при загрузке из ВСЕГО мира выводятся средняя длина связи
   (`meanLinkLength` — от неё пороги и потолки) и средняя площадь клетки (нормировка масс в
   `buildMasses`). С телами в рантайме добавление тела меняло бы физику живущих. Эти
   числа фиксируются при создании мира (`WorldScale`): из первой загрузки — как сейчас —
   или заданы явно (игра). Размер ячейки сетки контактов — от наибольшего радиуса:
   тело крупнее разрешённого — пересборка сетки (редкий случай).
2. **Ёмкость.** Массивы по частицам, связям, треугольникам и рёбрам заводятся с запасом
   ёмкости; `n` — число занятых. Не хватило — удвоение с копированием (редко; игра задаёт
   ёмкость сразу).
3. **Добавление тела — дописывание.** Частицы, связи, рёбра, треугольники, кости, мышцы,
   организмы, пары покоя, смежность контактов, контур, блоки решателя и план связей
   дописываются по новому телу, без прохода по миру. Стоимость — по размеру тела.
4. **Удаление — гибель на месте, затем уплотнение.** Частицы тела замораживаются, связи и
   треугольники гаснут, контакты их отпускают (как гибель клетки). Когда удалённых
   набирается четверть мира, мир уплотняется: удалённые тела выбрасываются, остальные
   сдвигаются вниз с сохранением порядка (решение 26.10 — вместо арен с дырами, как в
   `Entity.reserveRange`: арены потребовали бы переделать все структуры с общим порядком).
   Клиент обращается к телу по номеру тела, частицы — `bodyFirst` + смещение.
5. **Рост — `activate`.** Тело добавляется сразу всей раскладкой генома; нерождённые
   клетки — частицы с `invMass = 0` без контактов, их связи и треугольники мёртвы.
   Рождение клетки оживляет её и её рёбра — обратное разрыву обновление контура.

**Проверка-оракул.** Загрузка N тел разом и N добавлений по одному в пустой мир (с теми
же постоянными мира) обязаны дать побитово один мир: хэши на каждом тике совпадают.
Так проверяется каждая дописываемая структура. Дальше — добавление и удаление посреди
прогона: повтор побитово (две одинаковые записи), CT_BPCHECK без пропусков, trapHunt.

Подэтапы: A2.1 постоянные мира и ёмкость; A2.2 дописывание тела (оракул); A2.3 удаление и
повторная выдача диапазонов; A2.4 рост (`activate`).

  мира; записи окна побитово.
- ✔ **A2.2** `PhysicsWorld.addBody` / `BodyState.appendBody` (topology/BodyAppend.kt):
  частицы, рёбра и смежность (`BakedTopology.append`), кости, мышцы, связи, треугольники,
  организмы, сон, пары покоя (канонический порядок в строке — на физику не влияет,

- ✔ **A2.4** рост по клетке (topology/BodyGrowth.kt). `addBody(def, born)` дописывает тело

  импульса не считают нерождённую закреплённой. Удаление недоросшего тела выводит его
  нерождённые рёбра из списков. Проверки:
  - `GrowthCheck`: born = «все» ≡ без born побитово; тело 947 клеток растёт из одной под
    гребком, второе удаляется недоросшим, 760 тиков — один поток = 7 воркеров побитово,
    CT_BPCHECK без пропусков; целость выросшего 2520 из 2617 рёбер против 2617 у целой
    копии (порог 95%).
  - `PartialBodyCheck`: недоросшее тело маской ≡ вырезанное из тех же клеток (K = 200…947,
    ни одного разрыва под гребком); 400 рождений на месте покоя ≡ маска по составу блоков
    решателя и целы под гребком. Этот оракул поймал ошибку: `updateBoundaryLinkLimit`
    вынимал нерождённую связь из блоков насовсем (464 разрыва вместо нуля).
  - Ограничение: клетка прирастает только к своему организму. Если тело успело порваться
    и сосед в другом куске, связь к нему не рождается (слияние организмов — отдельная
    задача).
- ✔ **Дорастание новорождённой ткани** (26.10, `easeNewborn`). Рождение в обрывок мышцы,
  сжатый гребком (длины покоя ×0.5, а соседи по обрывку растянуты), давало рывок при любой
  мгновенной постановке. Теперь длина покоя новой связи и площадь покоя треугольника
  начинаются с фактических и за `BIRTH_GROW_TICKS` = 10 тиков подходят к своим (темп
  сокращения мышцы, который ткань выдерживает). Раз в тик, только по списку дорастающих,
  в подшаге ничего не добавлено. Выросшее под гребком тело: 2483 → 2532 рёбер из 2617
  (целая копия — 2617). Отвергнуто: подгонка точки рождения по нынешним длинам
  (переворачивает треугольники, 1706 из 2617).
- ✔ **Свободное место при рождении** (26.10, `freeSpot`). Под сокращением край недоросшего
  тела сползает в пустоту, где позже родится клетка, и новорождённая ложилась поверх
  соседа — глубокий контакт убивал обоих (тело 947 клеток в одиночку под гребком: 26–33
  таких рождений при любом темпе; без гребка — ни одного). Занявшая клетка почти всегда в
  2–3 рёбрах по графу тела, поэтому смотрятся рождённые клетки трёх колец (десятки, только
  в момент рождения), и точка выталкивается из зоны смерти соседа с запасом ×1.1. Шесть
  ростов (два тела с мышцами × три темпа), порвано рёбер / погибло клеток: без поиска
  480 / 82, с поиском 216 / 39. Отвергнуто: выталкивание до суммы радиусов (683 / 137 —
  щель у большого тела закрыта целиком, клетку загоняет в соседнюю ткань); отсрочка
  смерти на время дорастания (почти без пользы, откачена); медленный рост (хуже — тело
  дольше недоросшее).
- ☐ **Остаток при росте под гребком.** Около половины прежних потерь: дальние куски тела
  и чужие тела в поиске не участвуют (нужна свежая сетка контактов), а у закрытой целиком
  щели свободного места нет. Если игре понадобится больше — клетка, рождающаяся маленькой
  и раздвигающая соседей (растущий радиус контакта), или правило игры «не делиться в
  сжатой мышце».

## 3. Игра и библиотека — этап B, адаптер в `:core`

| Игра | Библиотека |
|---|---|
| `CellEntity` + `ParticleEntity` | частица тела (1:1), смещение в арене тела |
| `LinkEntity` | связь; длина покоя — из запекания |
| `TriangleEntity` | треугольник площади |
| кератиноцит, стереоцит (кость) | кластер кости (shape matching) |
| миоцит | мышечный кластер; сокращение — `setMuscles` |
| жгутоцит, цилиоцит | внешний импульс до шага |
| `OrganEntity` (арена) | тело `BodyId` и его арена |
| остров террейна, стенка | неподвижное тело |
| `SubstancesEntity` | свободная частица |
| `GridManager` (столкновения) | широкая фаза библиотеки; игре сетка остаётся для зрения и запахов |
| феромоны | остаются в игре (поле на сетке) |

Адаптер — новый пакет `core/.../physics/bridge` с узким API. `PhysicsBridge` создаёт тела
из запечённого генома (готовая выгрузка — `editor/baking/BodyExport.kt`), применяет входы
тика и раздаёт события системам игры. Старые `ParticlePhysicsSystem`, `LinkPhysicsSystem`,
`CollisionManager`, `MovementManager` удаляются в той же ветке, без переходного периода.

## 4. Потоки

- Один пул на процесс: `PhysicsWorkers` — обёртка над `ParallelExecutor` игры. Два пула на
  одни ядра дрались бы в спин-петлях. Раздача у игры динамическая; результату это не
  мешает, теряется только привязка блоков к L2 ядра — замерить.
- Пороги спина — из `PlatformTuning` (на телефоне короткий спин).
- TeaVM — без воркеров (`workers = null`), результат тот же.
- Миры меньше `PARALLEL_MIN_PARTICLES` (4000) — в одном потоке.

## 5. Команды, журнал, отчёты

- Действия игрока, трогающие физику (захват мышью, подсадка, удаление), идут через уже
  существующие команды (`commands/GameCommand.kt`) и применяются в тике симуляции до
  `step()`. Путей мимо команд нет.
- Мышцы и импульсы выводятся из детерминированной нейросети — в журнал не пишутся.
- Материал физики (`PhysicsConfig.snapshot`) — во вложения сессии. Число воркеров и порог
  параллельности туда не входят (уже так): повтор при другом числе воркеров — проверка.
- `StateHash.VERSION++` и новый номер формата сессии при подключении.

## 6. Рендер

Снимок для отрисовки (тройной буфер, `render-interp` от 21.10) берёт позиции из массивов
мира физики в конце тика. Интерполяция по подшагам, как в стенде, — по желанию. `:render`
о физике не знает, как и сейчас.

## 8. Риски

- **Состояние широкой фазы в снимке** (A4) — самое тонкое место побитового сохранения.
- **Рост в рантайме** — решается полной раскладкой арены с самого рождения (п. 2).
- **Один гигантский организм** делится только блоками: общий предел длины, ориентация и
  вязкость у него в одном потоке (TODO «Потоки: что осталось»).
- **Много субстанций** — замер 26.10 (`FreeBench`, сцена 30k + 5000 частиц вдали от тел,
  машина была нагружена — числа ориентировочные): частица стоит ~1.2 клетки тела (тик
  145 → 173 мс одним телом из клеток); пул — ещё ~10–20 мс за ~3200 нерождённых слотов
  (каждый — свой организм и блок решателя). Прежняя запись: не мерили: каждая — свой организм, сон и раскладка по организмам на
  десятках тысяч одиночных частиц не проверены. Пока их мало — не мешает; замер, если
  станет много.
- **Телефон**: раскладка массивов ART и цена double — замерить на первой сборке под
  телефон (TODO, раздел Android).
