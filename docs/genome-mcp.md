# Genomeia MCP для настольной игры

Один раз подключите Genomeia к своему локальному помощнику. После этого можно попросить, например, «Уточни размер организма и покажи макет в Debug. После моего согласия подбери геном и проверь ход на дистанции».

## Подключение

1. Распакуйте комплект в постоянную папку с правом записи. Для JAR нужна Java 21. В Windows откройте **Play with MCP.cmd**. В Linux/macOS запустите `java -jar Genomeia.jar --enable-mcp`. На время работы с помощником оставьте это окно открытым.
2. Откройте **MCP setup.cmd** или выполните `java -jar Genomeia.jar --mcp-config`. Игра напечатает команды с абсолютными путями к Java и этой копии игры.
3. Для **Codex** выполните выведенную строку `codex mcp add …`. Для **Claude Code** выполните строку `claude mcp add …`. В Windows строки предназначены для PowerShell. В **Claude Desktop** добавьте выведенную запись `genomeia` в раздел `mcpServers` конфигурации локальных серверов. Сохраните уже существующие записи.
4. Перезапустите клиент или откройте новую сессию. Попросите «Вызови get_status в Genomeia и назови экран игры». В ответе должен быть текущий экран, например `MenuScreen`. Если игра закрыта, каталог инструментов остаётся виден, а вызов вернёт сообщение о запуске с `--enable-mcp`.

Актуальные настройки клиентов приведены в [документации Codex](https://developers.openai.com/codex/mcp/), [Claude Code](https://code.claude.com/docs/en/mcp) и [Claude Desktop](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop).

Игра и локальный MCP-клиент должны работать под одной учётной записью. При перемещении JAR повторите настройку с новым путём. Обычный запуск игры оставляет мост выключенным. Игра завершает соединение при закрытии окна. Помощник получает данные игры через свой клиент.

## Что можно прочитать

| Запрос | Результат |
| --- | --- |
| `get_status`, `list_genomes` | Текущий экран, маршрут, доступность проверки роста, черновики и имена геномов игрока и встроенной библиотеки. |
| `get_catalog` | Ключи и описания доступных клеток, формулы, правила деления и готовый пример стадий в формате установленной игры. В редакторе учитывается его палитра. |
| `read_genome` | Исходные стадии, деления, мутации и связи. Режим `cells` возвращает геометрию взрослого тела с ID клеток, а `links` — пары ID концов физических связей. Источником служит имя из библиотеки, ID черновика или `editor:` для открытого редактора. |
| `read_growth` | Клетки на выбранном тике роста черновика или открытого редактора. Ответ содержит `lastTick`. Позиции соответствуют раскладке, которую показывает редактор. |
| `read_state` | Между двумя тиками мира снимает страницу клеток, организмов, физических или направленных нейросвязей. Для клетки доступны положение, скорость, энергия и сигналы. В открытом редакторе читает выращенное тело и сообщает выбранный тик шкалы. |
| `measure_organism` | Для одного живого организма возвращает номер тика, стадию, центр тела, среднюю скорость, сумму энергии и число клеток каждого типа. |

## Проверка движения на дистанции

В играющей симуляции найдите взрослую особь через `read_state(view="organisms")`. Выберите направление вперёд по исходной ориентации тела, например от задней клетки к голове. Передайте его в координатах мира один раз. Задайте дистанцию в клетках мира и длительность замера в тиках.

```json
{"organism":0,"generation":1,"forwardX":0,"forwardY":1,"distance":8,"ticks":1200,"windowTicks":60,"maxBackwardFraction":0.1,"minForwardEfficiency":0.85}
```

Передайте эти аргументы в `start_motion_trial`, подставив реальные слот и поколение. Вернувшийся `motion:…` используйте в `read_motion_trial(id)`. Для визуальной сверки живого тела вызовите `preview_organism(organism, generation)`: снимок рисуется в Debug Original с текущими позами клеток. На паузе измерение ждёт. `cancel=true` завершает его досрочно. Потеря клеток, гибель или смена мира прерывают наблюдение. Можно вести один замер одновременно.

Инструмент снимает центр взрослого тела каждый игровой тик. В результате есть длина пути, итоговое продвижение вдоль исходной оси, пройденное назад расстояние, максимальный откат и боковое отклонение. `windowProgress` показывает подписанное продвижение на каждом интервале. `firstReachedAtTickOffset` отмечает первое достижение цели. Для `sustainedForward=true` нужно завершить весь замер за целевой отметкой или на ней, продвинуться вперёд в каждом интервале и уложиться в допустимую долю обратного хода. По умолчанию она равна 10% суммарного хода вдоль оси. Для строго однонаправленного движения задайте ноль. Для обратной связи спайковой сети свободная палитра MCP разрешает скрытую клетку `speed_sensor`. Она измеряет скорость вдоль оси самой клетки. Для сравнения походок повторяйте одинаковый маршрут при тех же параметрах и оставляйте впереди места больше, чем заданная дистанция. При проверке гусеницы на физике 0.2.3 смена фазы отпускания присосок меняла знак продвижения. Для шагающего тела сравнивайте обычный прогон и контрольные варианты с выключенными мышцами и присосками. Проверяйте также число сохранившихся клеток и боковой уход.

Для отбора на прямой дорожке задайте `minForwardEfficiency`. Значение 0,85 требует, чтобы продвижение вдоль исходной оси составило хотя бы 85% длины всей траектории. Каждый шаг вбок увеличивает длину пути, даже если потом тело вернулось на исходную линию. Измеренное отношение возвращается в `forwardEfficiency`. По умолчанию порог равен нулю.

Чтобы проверить вклад спайков, сравните один и тот же организм на одинаковых дорожках в трёх состояниях: с исходными весами, с обученными весами и с выключенным источником спайков. Для первых двух замеров зафиксируйте веса на время оценки. Сохраняйте исходный геном отдельно, чтобы сравнить именно обучение весов при неизменных форме тела и разводке связей. Сравнивайте на нескольких начальных ориентациях и проверяйте путь, пройденный до касания стены.

## Макет до программирования генома

1. Уточните **максимальную ширину и высоту взрослого тела в клетках мира**. Для этого служит `request_body_scale`. Клиент с поддержкой форм MCP покажет оба поля. Остальные клиенты получат вопрос, который помощник задаёт в чате и ждёт ответа. Если пользователь уже задал размеры, используйте их. Размер 4 × 4 — пример.
2. Изучите несколько встроенных организмов через `list_genomes` и `read_genome`. Сопоставьте типы, радиусы и координаты из `cells` с парами из `links` по ID. Для походок удобно начать с `bundled/Leech` и `bundled/Big walker`. Используйте страницы `offset` и `limit`. Игра держит в памяти четыре последних прочитанных встроенных генома.
3. Составьте `create_body_layout(width, height, cells, links)`. Начало координат находится в левом нижнем углу согласованной области. Индекс клетки в массиве станет её ID, начиная с 0. Укажите `type, x, y` и при необходимости угол в радианах. По умолчанию радиус равен максимуму редактора **0,5**. Меньший радиус допустим только для тонкой детали, явно указанной пользователем. У соответствующей клетки заполните `fineDetailReason`. Каждая физически соединённая пара должна иметь строгое перекрытие: расстояние между центрами меньше суммы радиусов. Все диски целиком помещаются в область, тело связно и содержит хотя бы одну клетку `leaf`.
4. Вызовите `test_body_layout(id, ticks)`. Игра сразу помещает клетки и связи в отдельный мир и включает обычную физику и обмен энергией. По умолчанию проверка длится 600 тиков. Начальный запас каждой клетки — половина её ёмкости. Сравните число живых клеток, пары, разошедшиеся после прогона, и запас энергии в начале и в конце. `lastQuarterEnergyChange` показывает, продолжает ли запас падать к концу испытания. В `eyeProbes` каждый глаз по очереди смотрит штатным лучом на отдельную внешнюю мишень у границы видимости. Если обзор закрыт клеткой, в ответе указан её ID. Наличие Leaf само по себе ещё не гарантирует достаточного питания. Такой прогон проверяет взрослую конструкцию в течение заданного времени. Рост и работу будущей нервной сети проверяют отдельно.
5. Покажите пользователю PNG из `preview_body_layout(id, view="settled")`. Это **Debug Original** после прогона. Для крупных организмов передайте `size=1024`, чтобы рассмотреть отдельные клетки. Для сравнения исходная раскладка доступна как `view="placed"`. Дождитесь явного согласия. Только затем вызовите `approve_body_layout(id)`. При исправлениях создайте новый макет и покажите его заново.
6. Передайте одобренный `layoutId` в `create_genome`. При подборе стадий сохраняйте ID клеток. `validate_genome` возвращает `layoutComparison` с расхождениями по клеткам, радиусам, связям, зазорам и размерам. Ошибка позиции измеряется после совмещения переносом и поворотом, в исходном масштабе. При утверждении можно задать `positionTolerance` в единицах мира, по умолчанию 0,1. Перед сохранением проверьте также Debug-превью выращенного генома.

Через `get_status.bodyLayouts` и `read_body_layout` можно вернуться к координатам, связям, исключениям для тонких деталей и результату испытания. Макеты хранятся в памяти текущего экземпляра игры, одновременно доступны восемь последних. До вызова `save_genome` библиотека игрока не меняется.

## Стадии роста и сохранение

Если соседние мышцы должны получать один сигнал, проведите к суставу один моторный вход и разветвите его на месте. Сохраняйте независимые входы для мышц, которым нужны разные фазы. Передача через промежуточную клетку добавляет задержку, поэтому после изменения разводки перепроверьте фазы мышц и присосок в симуляции.

Проверяйте рост из зиготы в нескольких местах мира. Сверяйте ID выращенных клеток и пары концов физических связей с макетом. Если между двумя клетками виден просвет, проверьте обе величины отдельно: сохранилась ли связь и насколько расстояние между центрами превысило сумму радиусов. Наблюдайте также моменты деления, окостенения и максимального сгибания сустава.

Получите `exampleStages` из `get_catalog` и передайте массив в `create_genome(name, stages, layoutId)`. Первая стадия начинается с зиготы с ID 0. Ключ в `cellActions` обозначает исходную клетку. При делении ребёнку нужны свободный ID, тип и угол в радианах. В `physicalLink` ключ обозначает ID второй клетки, длина задаётся в единицах мира. Физические связи с уже выросшими соседями задаются при делении. Если две соседние клетки должны быть соединены, запланируйте их рождение на разных стадиях. Мутация позволяет настроить нейросвязи у выросших клеток. Ключи типов и формул можно копировать из справочника. Стадии существующего организма можно прочитать через `read_genome`.

Черновик получает собственный `draft:…` и хранится в памяти окна игры. Для другого варианта создайте новый черновик с изменёнными стадиями. В памяти остаются восемь последних черновиков. Инструмент принимает до 512 стадий, 8192 действий и 1024 клетки на создаваемый геном. Большие библиотечные геномы доступны для чтения по страницам с `offset` и `limit`.

В главном меню или в разделе «Геномы» вызовите `validate_genome(id)`. Игра вырастит организм штатным расчётом редактора, построит связи, посчитает взрослые клетки и подготовит снимок. Ошибки структуры содержат стадию и ID проблемной клетки, когда они известны. Открытый рабочий редактор использует тот же расчётный мир, поэтому для первого выращивания черновика нужно выйти из редактора. Проверка описывает рост. Поведение взрослого организма можно наблюдать отдельно в запущенном мире.

Вызовите `preview_genome(id)` для получения PNG прямо в ответе MCP. Затем `save_genome(id)` сохранит запечённый файл через библиотеку и вернёт его имя. Из главного меню откроется экран «Геномы». При совпадении имени с другим содержимым игра подберёт свободное имя. Повтор того же сохранения вернёт существующий файл. Пользовательские файлы располагаются в папке `genomes` рядом с игровым JAR. Для работы с существующей библиотекой используйте папку своей игры или скопируйте нужные .genome в новую установку.

## Сборка и проверка из исходников

В корне проекта запустите `./gradlew :lwjgl3:genomeMcpDist` (Windows: `gradlew.bat :lwjgl3:genomeMcpDist`). Комплект появится в `lwjgl3/build/genome-mcp`. После `gradlew clean` каталог сборки удаляется, поэтому для постоянной игры скопируйте комплект отдельно.

Сквозная проверка запускает независимые процессы игры и стандартного ввода-вывода, использует временную библиотеку и реальный OpenGL. Для проверки нужны Java 21, Node.js и графический сеанс.

```
node lwjgl3/src/verification/mcp/smoke.mjs lwjgl3/build/genome-mcp/Genomeia.jar
node lwjgl3/src/verification/mcp/smoke.mjs lwjgl3/build/genome-mcp/Genomeia.jar GoGenomeEditor
node lwjgl3/src/verification/mcp/smoke.mjs lwjgl3/build/genome-mcp/Genomeia.jar GoSimulation
```
