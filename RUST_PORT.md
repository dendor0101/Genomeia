## Задача автора (26.11 вечером, дословно)

«Сделай версию на rust возьми наработки в "Физика на Rust: эксперимент производительности" до обнови изменения и
сделай воркеры что бы была параллельность - важна побитовая схожесть и производительность».

Условия: Kotlin — эталон; закон до следующего демо не меняется; правка битов в Kotlin ради скорости Rust — только с
согласия автора. Rust нужен только для Android (автор 26.11), ПК — для тени и проверок. Коммит — по просьбе автора.
Параллельно на этой же машине работает форк CUDA: замеры времени на ПК согласовывать, телефоны — свободно.

## Подход

Старый перенос (17 тыс. строк Rust) писался под закон 11.11 в double; с тех пор физика на Kotlin изменилась в 70 из
77 файлов (+8 тыс. / −1.8 тыс. строк) и целиком перешла на float. Поэтому каждый модуль Rust переписывается заново по
нынешнему файлу Kotlin, дословно (тот же порядок операций с плавающей точкой, float/double как в Kotlin, без FMA и
fast-math), а старый модуль — образец устройства (JNI, отпечаток, снимок, `jmath.rs`, раскладка по крейтам).
Проверка — тень: `-PrustShadow` у любого теста, стенда и проверки, сверка отпечатка состояния после каждого тика,
строгий режим `-Dgenomeia.physics.rust.checkOps=true` — после каждой операции мира.

Острова в первом проходе не переносятся (биты от них не зависят); у Rust своя раздача работы по воркерам с теми же
блоками, швами, волнами, кусками и порядком слияния, что задают биты.

## Веха 5 (27.11): воркеры в Rust

Пул `solver/pool.rs` — как `SpinPhysicsWorkers`: вызывающий поток работает сам, куски раздаёт атомарный курсор;
курсор, счётчик незавершённых, эпоха и признаки сна — каждый в своих 128 байтах (false sharing); спин 200 000 проверок,
потом сон с удвоением паузы до 2 мс; без блокировок и выделений в тике; общий пул на число воркеров. Мир заводит пул при
`WORKERS > 1` (у тени — по настоящему пулу мира Kotlin), стадии берут его при `n ≥ PARALLEL_MIN`, как в Kotlin.

На воркерах (`solver/parallel.rs`, по образцу `ParallelBlocks.kt`):
- блоки обеих чётностей (`dispatchOrder`), остановка блока перед событием топологии и доработка в одном потоке по
  возрастанию номера, блоки тел из `computeSerialBlocks` — в одном потоке; швы; общий проход пределов по наборам;
- проходы скоростей (до, после, лёгкий, доделка касаний), учёт импульса за тик (начало и снятие: поштучное по частям
  кусков, суммы по кускам и слияние в их порядке), суммы центра масс для запаса среды, плата среде, снятие и возврат
  дрожи, сопротивление рёбер контура и ориентация по наборам блоков, вязкость по наборам.
- решение касаний (`contacts/parallel_solve.rs` ← `ParallelContactSolve.kt`, от 2048 касаний за подшаг): куски
  касаний, силы по корзинам частиц в исходном порядке обхода, потолок, урезание множителей, применение, кости в
  порядке первого касания;
- мышцы: подшаговая плавность множителей (от 4096 записей, куски по 2048) и кольца шага мышц
  (`solver/muscle_rings.rs` ← `ParallelMuscles.refreshRings`, от 256 сдвинувшихся клеток: куски по блокам, три цвета
  блоков, буферы кусков сливаются по порядку);
- подготовка касаний после списка пар (`contacts/parallel_prepare.rs` ← `ParallelPrepare`, `prepareFused`, а также
  `ParallelCcd`, `ParallelPierce`, `ParallelBuild`; от 1024 пар): куски по 64 пары (не больше 16 на воркер) копят у
  себя пары для тела CCD (отсев `ccd_skips`), пробитые рёбра и перекрытые пары — всё в порядке пар; тело CCD идёт по
  найденным парам подряд, рёбра пробоя склеиваются в порядке кусков, касания пишутся со смещения куска (запись — по
  воркерам от 256 касаний). Удар CCD — запасной путь: CCD доделывается, пробой и касания — заново отдельными проходами
  по воркерам.
- широкая фаза: поиск пар перекладываемых вершин (`contacts/parallel_broadphase.rs` ← `ParallelCandidates`, от 64
  вершин: куски moved по 16 вершин, у воркера своя пометка и свои буферы DDA, буферы кусков склеиваются по порядку);
  границы отсева пробоя — по воркерам и без слитой подготовки, от 512 подвижных вершин (`BOUNDS_PARALLEL_MIN`; в
  Kotlin при парах меньше 1024 — в одном потоке, на биты не влияет: вершина пишет только свои ячейки);
- раз в тик: пластика (куски по номерам или наборы блоков со сном), долгая инверсия (наборы по воркерам, гибель
  после барьера по возрастанию номеров — как у Kotlin с воркерами), слияние групп импульса по касаниям (от 1024
  касаний: ключи пар организмов по кускам, пометка неподвижных — атомарной записью, слияние по порядку кусков).
- остаток широкой фазы (тот же файл): уехавшие вершины (`ParallelMoved`, от 1024 подвижных) и уцелевшие пары
  (`ParallelPairs.keep`, от 1024 пар) — фильтры с сохранением порядка (счёт по частям, смещения, запись со своего
  места); перекладка вершин по частям сетки (`ParallelReinsert`, от 64 перекладываемых: подвижная сетка — по части
  на воркер, `shards`/`shard_of`/`reshard` как в Kotlin; след — по частям moved, перекладка — по частям сетки); слияние
  списка пар по ключам-разделителям (`ParallelPairs.merge`, от 1024: часть берёт из каждого источника ключи между
  своими разделителями, нижние ключи приходят отсортированными прогонами кусков поиска); кластеры костей в
  подготовке касаний (`ParallelBones`, от 64 кластеров).
Теперь всё, что в Kotlin вне островов идёт по воркерам, идёт по воркерам и в Rust; острова в Rust не перенесены.

### `bugReplayCheck` под тенью (27.11)

`gradlew --no-daemon :lwjgl3:bugReplayCheck -PrustShadow` — сценарий игрока целиком (рост, команды, мир с рельефом на
74 тыс. частиц) с двойником на Rust у каждого мира физики и сверкой отпечатков после каждого тика. Первый прогон
(сборка до переноса остатка широкой фазы): тень сверила **2948 тиков в 107 мирах — ни одного расхождения**, но запись
сценария упала по таймауту «сценарий завис на шаге 12»: тень на мире в 74 тыс. частиц замедляет тик, а ожидание шага в
`BugReplayCheck.kt` было жёстко 300 с — свойство `bugReplayCheck.timeoutSec`, которое ключ `-PrustShadow` в корневом
`build.gradle` ставит в 3600, код не читал. Исправлено: таймаут записи и повтора берётся из свойства (без него —
прежние 300 с).

Второй прогон (вся широкая фаза и кости на воркерах, таймаут 3600 с) — **PASS**: запись — тень сверила 4686 тиков в
118 мирах, повтор — 4679 тиков в 118 мирах, расхождений нет; сам повтор: UI-команд 114 из 114, SIM-событий 2386 из
2386 (контрольные суммы совпали), сверок состояния мира 66 из 66, прежняя карта побайтно та же. Время прогона —
около 25 минут (без тени — минуты).

### Профиль Rust на A21s (27.11, simpleperf, мир по умолчанию, 7 воркеров, до переноса широкой фазы)

`rprof.sh RF8N83B3NKP a21s-w7 5000 7 40 80` (скрипт черновой папки: `simpleperf record -e task-clock -f 1000` вокруг
стенда, отчёт по библиотеке Rust — поток и функция). Из времени шага Rust главный поток: ~30% — работа в одном
потоке, ~23% — ожидание воркеров на барьерах (`Workers::run`), остальное — своя доля параллельных кусков; воркеры
простаивали около половины времени. В одном потоке (доля шага Rust): широкая фаза `update_candidates` с поиском пар
~8%, границы отсева пробоя ~3.7%, пластика (внутри `solve_tick`) ~5%, CCD, сборка касаний, вывернутые — по 1–1.5%. Пар
в этом мире меньше 1024 — слитая подготовка не включается (у Kotlin тоже; Kotlin на этом мире островов не берёт:
выбор по замеру, `docs/physics/islands.md`). Ожидание на барьерах — неравномерность блоков: 14 блоков по 500
частиц на 7 воркеров, по одному блоку чётности на воркер; размер блока — часть закона (порядок решения), его не
трогаю.

`RustWorkersParityTest` (6): тела 40×30 (несколько блоков со швами), Rust при 2, 3 и 8 воркерах с параллельностью с
любого размера против Kotlin — побитово каждый тик: гребок с ударом-сдвигом, таран 20 и 80 ед/с с касаниями
(разрывы, гибель), рост с газом и уплотнением, газ на теле с мышцами (касаний до 3234, записей плавности до 5723),
газ на теле с ударами струёй (до 13 139 пар, слитая подготовка во всех 1200 подшагах, из них 2 — с обрезкой CCD,
то есть запасным путём), обе стороны с воркерами.

Замер — `gradlew :physics-lab:rustGenomeBench -Pcells=… -Pworkers=…` (RustGenomeBench.kt): сцена genomeBench `one`,
Kotlin в настройке игры (воркеры, острова по замеру) и двойник на Rust с тем же числом воркеров, шаги раздельно под
своими таймерами в порядке A B / B A, отпечатки сверяются каждые 30 тиков и в конце.

### Острова в Rust (27.11, перенесены)

Автор 27.11 утром: «Продолжай с растом и делай острова если это целесообразно». Целесообразно для телефонов: на мире
мелких тел Rust опережал Kotlin с островами лишь в 1.13–1.17 раза, и мешали ему барьеры и неравномерность блоков
(профиль выше), которые острова и снимают. Острова в Kotlin битов не меняют (сумма мира с ними и без одна), поэтому в
Rust они — чистая скорость, а сверка с Kotlin та же.

**Что перенесено** (около 2.1 тыс. строк в новых файлах и правки в стадиях):

- `solver/island_plan.rs` — разбиение (`TickScope.kt`: рамки тел с запасом, группы, области блоков, организмов и
  вершин, списки островов) и выбор режима по замеру (`IslandChooser`: прогрев 120 тиков блоками по 20, потом блоки по
  5, удержание 300–2400 тиков, порог 97%) — те же числа, что в Kotlin; замер у Rust свой (часы Rust).
- `solver/islands.rs` — область тика: `SCOPE_WORLD` (мир без островов), k ≥ 0 (остров k), `SCOPE_ALL`. Её обходят все
  стадии подшага: блоки и швы (`ConstraintBlocks::scope`, обход `BucketWalk`), диапазоны частиц сна, организмы (импульс,
  дрейф, среда), вершины касаний (`BoundaryContacts::scope`), куски сумм (`PassChunks::restrict`).
- `solver/island_run.rs` — прогон острова на воркере (`IslandRun.kt`): тень состояния, снимок острова в начале тика,
  откат на событии, слияние итогов, перевод острова в мир.
- `contacts/island_fork.rs` — копия касаний острова (`BoundaryContacts.islandFork/setIsland/mergeIslandFork`).

**Тень острова.** В Kotlin тень — мелкая копия `BodyState`, у которой общие с миром массивы. В Rust это побитовая
копия структуры (`ptr::copy_nonoverlapping`) в `Box<MaybeUninit<BodyState>>`, которая никогда не освобождается: её
общие поля принадлежат миру. Свои части тени (вид раскладки и сна, список слияний импульса, копия касаний, куски,
черновики) ставятся в неё `ptr::write` из комплекта воркера и в конце тика забираются обратно `ptr::read`. Копия
касаний собирается ПОЛНЫМ литералом структуры: общее поле — копия поля мира, своё — из комплекта, поэтому забытое
поле не разделит память с миром молча, а не соберётся. Остров пишет только свои частицы, связи, треугольники, кости и
организмы — как в Kotlin.

**События в острове.** Kotlin прерывает остров исключением в четырёх местах (пробой, гибель, пробуждение соседа,
событие предела длины). В Rust — признак `isl.abort` (не размотка стека: размотка освободила бы общие с миром части
тени) и проверки после итераций, пределов и касаний; остров восстанавливается из снимка и идёт подшагами мира вместе с
ним — как шёл бы без островов. Липкие связи (`StickyJoints`) и тяга мышью решаются только в области мира, как в Kotlin.

**Не перенесено:** широкая фаза острова между тиками (`IslandBroadphase`, 26.11) — копия касаний острова собирает её
каждый тик заново, биты те же (полная пересборка и пересчёт по ходу дают одну сумму, опыт 25.11); в Kotlin запас давал
около 7% работы островов на ПК.

**Проверки.** `RustIslandsParityTest` (новый, 4 сцены, Rust при 1, 2, 3 и 8 воркерах против Kotlin, отпечаток после
каждого тика): тела порознь (острова в 60 из 60 тиков), событие внутри острова (Kotlin откатил остров — Rust тоже,
биты те же), откат КАЖДОГО острова (`ISLANDS_ROLLBACK_ALL=1` — проверка полноты снимка), группа сталкивающихся тел и

Острова Kotlin не меняют физику, но меняют кэш широкой фазы (сброс на смене области) и оставляют в объекте касаний
мира к концу тика только касания области мира. Поэтому эти два раздела отпечатка (`broadphase`, `contactList`)
сверяются строго, когда в Kotlin острова выключены (`ISLANDS=0` — так идут тесты), и пропускаются, когда могут

## Ссылки Kotlin, которые в Rust стали параметрами (проверить при переносе BodyAppend, WorldCompaction, снимка)

- Касания держат ссылки на массивы хозяина (organismOf, noContact, group, pressure, boneOf, contactRamp,
  immuneStamp, lastInvMass). В Rust хозяин передаёт живые массивы (`ContactCtx`). Расходится это с Kotlin только в
  окне между пересозданием массива хозяина и переустановкой ссылки — сверить по каждому пути пересборки.
- `attachSurface` в Kotlin — ссылки на массивы LocalSurface; в Rust копия, а `update_surface` переносит строки
  задетых вершин. Поверхность пишет только строку своей вершины. Опасное место: `reconfigure` после attach в Kotlin
  может писать В массивы поверхности (adj/bndOther при достаточной ёмкости) — в buildContacts поверхность тут же
  заводится заново, в других путях — проверить.
- `lastInvMass` после пересоздания `invMass` (дописывание тела) в Kotlin указывает на старый массив до следующего
  prepare; влияет на `touchesStatic` (полная перестройка кандидатов) — повторить при переносе BodyAppend.

Не переносится: `reference/ReferenceSolver` (эталон стендов), `diagnostics/*` (Rust их ключи не принимает),
острова (`TickScope`, `IslandRun`, `IslandChooser`, `IslandBroadphase`) — в первом проходе, `DistanceSweepOrder`.
